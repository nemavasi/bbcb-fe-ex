# ADru на чистом Component Pascal

`ADru` — учебные примеры по алгоритмам и структурам данных
(Ф. В. Ткачёв, «Информатика-21»), 35 модулей `ADruS13` …
`ADruS48_PrioritySearchTrees`.

Подсистема перенесена **целиком на чистый CP** (ADR-247): в исходниках нет
`SYSTEM`, `WinApi`, `[union]`, `[untagged]` и машинного кода (`[code]`).
Зависимости — только CP-модули:

| Зависимость | Назначение |
|---|---|
| `i21sysIn` | ввод из выделенного текста/коммандера |
| `StdLog`, `Math`, `ObxRandom` | вывод, математика, случайные числа |
| `ADruS174_Texts` | строки/текст (учебный модуль) |

## `ADruS171_Files`

Единственный модуль, который в оригинале был платформенным:

```mod
IMPORT SYSTEM, Log := StdLog;

VAR u: RECORD [union]
    x: INTEGER;
    a: ARRAY 2 OF CHAR;
END;
```

`[union]` — расширение BlackBox: поля накладываются в памяти, поэтому
`a[0]`/`a[1]` — две 16-битные половины 32-битного `INTEGER` (CHAR в CP
16-битный). В стандартном CP такой прагмы нет, а простое удаление делает
запись последовательной и ломает `WriteInt`/`ReadInt`.

Порт заменяет приём арифметикой:

```mod
lo := x MOD 10000H;                 (* младшие 16 бит *)
IF lo < 0 THEN lo := lo + 10000H END;
hi := (x - lo) DIV 10000H;          (* старшие 16 бит *)
...
Write(r, CHR(lo));  Write(r, CHR(hi));
```

и восстанавливает знак при чтении. Формат (две `CHAR` на `INTEGER`)
сохранён; `Old` в книге всё равно делает `HALT(126)` — файлы живут только
в памяти, внешняя совместимость не нужна.

В комментариях модуля оставлен **оригинальный код** с `[union]` и
объяснение, почему он заменён: это важно тем, кто читает книгу и дошёл до
этого урока.

## Сборка и запуск

Внутри приложения:

1. открыть `ADru/Mod/S13.odc` (оригинальный документ) или
   `ADru/Mod/S13.Mod` (текст);
2. `Dev→Compile`;
3. выделить входные данные, `Dev→Execute` на `ADruS13.Run`
   (или другой процедуре урока).

Документация уроков — `ADru/Docu` (включая `Docu/ru`).
